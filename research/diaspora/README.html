Diaspora

I started Diaspora to build peer-to-peer money for the African diaspora. I want a person to own their keys, verify a payment, and still move a signed transaction when the usual connection goes down. This repository is where I keep the work and test those claims.

Set up the research build

Use Linux, macOS, or Ubuntu on WSL. The research tools require Python 3.10 or later, a C11 compiler, make, and OpenSSL development headers. For the inherited Core build, install the dependencies from the Unix, macOS, or Windows build notes. Start from the repository root.

git clone --branch diaspora/integration-lab https://github.com/ya1-oa/diaspora-v1.git
cd diaspora-v1
make -C research/weave-lattice-c test research
python3 -m unittest discover -s research/diaspora/lab -v
(cd research/diaspora/archive/weave-python && python3 -m unittest discover -s tests -v)

Run the wallet and payment lab

The wallet lab uses Bitcoin Core regtest with throwaway keys and test balances. The node listens for RPC on localhost and has no public peers. The script creates two descriptor wallets, mines spendable funds, prepares and signs a PSBT, round-trips a signed transaction through the packet files, broadcasts the recovered bytes, mines a confirmation and checks the receiver balance. The temporary datadir is removed after the node exits.

cmake -S . -B build -DBUILD_GUI=OFF -DENABLE_WALLET=ON
cmake --build build --parallel 2
bash research/diaspora/lab/wallet-smoke.sh "$PWD/build/bin"

You can pass an absolute path to a Bitcoin Core release binary directory to run the same baseline. The recorded run used Bitcoin Core 29.0. Use DIASPORA_RPC_PORT=28443 before the command if the default port is in use. A standalone Diaspora ledger wallet remains part of the production target.

Rehearse a radio transfer on two computers

  1. On the first machine, create public test data and packetize it. The lab uses a fixed header and 128-byte payload fragments, with at most 128 fragments.
  2. Copy the packet directory to the second machine over removable media or an isolated link. Try reordering the files or removing one to observe recovery and failure behavior.
  3. Reassemble the payload. Senders can resend missing fragments, and receivers may keep identical duplicates within the input limits.
printf 'Diaspora public radio lab\n' > public.txt
python3 research/diaspora/lab/packet.py encode public.txt packets
# Copy packets/ to the second machine, then:
python3 research/diaspora/lab/packet.py decode packets received.txt
cat received.txt

For the hardware milestone, put an adapter between this packet format and a TNC or modem. Start with an isolated audio cable or shielded bench setup with public test strings. Specify a KISS/AX.25 information-field mapping or a LoRa gateway mapping, measure the modem's effective payload and airtime, and add pacing and retry limits before enabling any over-the-air mode. An actual RF adapter and satellite gateway remain release gates. In the United States, Part 97 limits amateur transmissions involving pecuniary interest and messages encoded to obscure their meaning. Verify service, equipment, and payload eligibility before transmitting. See 47 CFR § 97.113.

The packet hash verifies reassembly integrity. A blockchain node still validates the recovered transaction. Keep private keys and wallet backups off this transport.

What the security tests establish

In the four-wave model, changing an early Cycle invalidates 9 later Cycles at width 3 and 15 at width 5. The linear hash-share baseline and the descendant count measure different things. L0 lacks a global fork choice, so it cannot establish a reversal threshold above 51%. See the L0 security model and the production gates for the comparison that still needs to be run.
