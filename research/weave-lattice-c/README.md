# Diaspora — Lattice Consensus Research / L0 (C11)

**Status:** Executable experimental model. Not production consensus, not a mainnet, and not a proof of 99% resistance.

This is an **isolated** research subtree: it does not alter Bitcoin Core or the repository's current runtime. The seed C code was an early development stage; this prototype is an additional research layer and is not asserted to replace the original architecture.

## Build tonight (Linux/WSL/macOS with OpenSSL development package)

Prerequisites: `make`, `gcc` or `clang`, `libcrypto` development headers (OpenSSL 3 or compatible).

```bash
cd research/weave-lattice-c
make test        # 15 deterministic tests
make research    # 3-wide & 5-wide lattice; 6 attacker hash shares
make sanitizer   # ASAN + UBSAN, rebuilds test binaries
make clean && make CC=clang test
```

On Windows: run these commands in WSL Ubuntu (`sudo apt install build-essential libssl-dev clang`). No Rust toolchain is needed for this first **C11** milestone; this is C library code with an explicit public header, ready for a future Rust `extern "C"` interface after the consensus semantics are hardened.

## What L0 implements

- SHA3-256 through OpenSSL EVP, fixed-size canonical big-endian encoding, domain-separated hash commitments.
- **One lattice, not three persistent chains**: each Cycle has >=3 mandatory contemporaneous parent dependencies. Current prototype uses `width` wave-local Cycles and accepts submissions in any slot order; there is **no privileged prev hash** and no permanent A/B/C lane.
- Every Cycle solves one independent SHA3 challenge *bound to each parent*, then one final proof bound to all the strand digests. All proof inputs include payload, wave, slot, width, difficulty, parent hashes, and historical anchors.
- Deterministic older Warp anchors, checked independently of parent requirements. No bonus work is credited for these references.
- Validation, pending-submission slots, ordered state replay, fork-world divergence test, and transitive rewrite/descendant tracking.
- Expected hash trial accounting (`cycles * (width + 1) * 2^bits`); this is **expected computational cost, not a fork-choice score**.
- A separate reproducible **baseline** gambler's-ruin hash majority simulator (not a Diaspora adversarial consensus simulator).

## Commands and sample measurements

```bash
./build/weave-research --width 3 --waves 4 --bits 8
./build/weave-research --width 5 --waves 4 --bits 8
./build/weave-research --attack --trials 20000 --rounds 100 --seed 42
```

When a first-wave Cycle changes in the width-3/four-wave model, 9 later Cycles become invalid; width-5 affects 15 later Cycles. **This is a causal dependency measurement, not a multiplier on the adversary's hash power.**

## Critical missing security properties

1. This L0 model is **synchronized by waves**, and has no permissionless anti-Sybil producer selection. A miner may create multiple competing candidates for a slot. A full asynchronous DAG and eligible frontier protocol are the next task.
2. There is **no global fork-choice rule, network, censorship resistance, dynamic difficulty, orphan buffering, transaction validation, finality, or persistent state**. Two disconnected groups can each construct locally valid but incompatible lattices. The experiment makes no claim that they automatically converge.
3. Adversary and honest miners can solve the same puzzles per SHA3 trial. Coupling increases honest costs too; the model does not establish protection against majority hash power.
4. Historical anchors are deterministic but not unpredictably generated by a bias-resistant public entropy beacon. The production anchor-selection protocol remains an open design decision.
5. `W_MAX_CYCLES` and `W_MAX_WIDTH` are bounded for test determinism; these are not network capacities. Complexity in replay and descendant lookup is intentionally simple.
6. Hashes, proof acceptance, and structural rewrites have been tested locally; no external code audit or proof of common-prefix/chain-growth properties has been performed.

## Why there is no automatic GitHub Actions workflow

The original repository has previously approached its included Actions-minute limit. This research branch deliberately adds **no automatic CI runs**. Testing is currently local and reproducible from the checked-in sources. A single narrowly scoped opt-in workflow can be added when the remaining Actions budget is confirmed.
